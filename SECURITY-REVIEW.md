# Bootstrap security review

**Verdict: FIX BEFORE USE**

- Scope: `yhersh/bootstrap`, branch `main`, commit `a0cd0dfee36e766bf0b91c7b4b039f54153f8e96`; assessed 2026-09-06.
- verified: all 27 tracked files, all 16 commits reachable from local refs, and all 29 distinct historical file versions were examined; no apparent reusable credential was detected.

- HTTPS protects against ordinary DNS/mirror tampering when the attacker cannot satisfy certificate/signature validation. DNS-record control plus valid certificate issuance, control of an authenticated origin, or control of the trusted signing source are stronger threats addressed above.
- Fedora curl uses redirects without an HTTPS-only redirect restriction. An authenticated origin could redirect a fetch to HTTP; require HTTPS-only initial and redirect protocols in a hardened loader.
- PowerShell's `Invoke-RestMethod` buffers a response before `Invoke-Expression`; it does not have Bash's identical streaming behavior. Neither documented launcher authenticates a syntactically valid shortened/replaced release.
- Fedora does not open the host firewall or install OpenSSH. Tailscale SSH intercepts tailnet traffic on its Tailscale address and depends on tailnet network/SSH policies; those account policies were not inspected.
- Fedora's hostname arguments are quoted; no shell/argument injection from the hostname was demonstrated. Its source-file/test-environment overrides assume a trusted invoking environment.

## Worker and public-repository observations

- verified: routing is an exact allowlist over the normalized URL pathname, with no filesystem lookup, dynamic import, outbound fetch, request reflection, or body processing. Query strings do not select script content.
- verified: traversal-shaped encodings and wrong extensions/case returned 404 in the local probes. Standard `/windows/../fedora` normalization selected the public Fedora route; it did not access a file or bypass authentication.
- verified: valid GET/HEAD script responses used the intended MIME type, version, CSP, and nosniff headers; HEAD lengths matched file byte lengths. Moving routes advertise 300-second caching; exact Fedora routes advertise one year; health and 404 use no-store.
- Low-impact protocol gaps: the handler constructs a nonempty 404 body even for HEAD, and 405 lacks an explicit cache policy. A real HTTP runtime may suppress the HEAD body. No cache-poisoning exploit was demonstrated; the Worker has no application Cache API usage.
- The source does not enforce HTTPS or add HSTS. Account-level redirects, edge caching, TLS settings, and deployed HEAD behavior remain unverified because DNS resolution failed.
- verified: both committed SHA-256 values match the current script bytes: Fedora `8f43f8486a92af92300224be633c429d3da98d66c31c4719154f179cb6275d0a`; Windows `74e8ef712e5b86996e708f37deea6ef54a44bd7ad1aeb53bbee44cd84306fa9b`. The Fedora checksum computation itself was correct in the local handler probe; Windows has no separate checksum/version route.
- verified: no configured Worker secrets, request logging, cookies, webhook URLs, private SSH keys, reusable auth tokens, or credential-bearing configuration were found in the tracked content/history. Wrangler observability is enabled; platform log retention/collection was not inspected.
- verified: `.yhersh/config.yaml` contains workflow policy and a public hostname, not credentials. Runtime state is ignored. The deleted `TASK.md` remains recoverable in history and contains a build brief, not a detected credential.
- Near-misses include the unignored secret-file names, machine-like hostname examples, and helpers that echo arbitrary arguments (`test/helpers/bin/tailscale:113`, `test/helpers/bin/sudo:61`). Normal Bats setup uses private temporary directories; helper fallback paths alone should not be treated as isolated or safe for real credentials.
